# v0.1.0

**Date:** 2026-10-29

## Context

PRD 초안을 기준으로 첫 구현을 수행했다. 구현 환경(Windows 11 10.0.26300, GitHub Desktop 3.6.7, 개발자 모드 켜짐)을 조사하면서 PRD의 두 가정이 현재 환경과 맞지 않음을 확인했다.

## Observation

측정/확인된 사실:

- 이 PC의 `PATH`에서 확인되는 GitHub Desktop CLI는 `%LOCALAPPDATA%\GitHubDesktop\bin\github.bat`이다. `github.exe`는 확인되지 않았다.
- `github.bat`는 `app-3.6.7\resources\app\static\github.bat`를 호출하고, 그 파일은 `ELECTRON_RUN_AS_NODE=1`로 `GitHubDesktop.exe cli.js %*`를 실행한다.
- `HKLM\...\AppModelUnlock`의 `AllowDevelopmentWithoutDevLicense`와 `AllowAllTrustedApps`가 모두 1이다.
- 레거시 레지스트리 키 `HKCU\Software\Classes\Directory\Background\shell\GitHubDesktop`와 `%USERPROFILE%\Open-GitHubDesktop.ps1`이 둘 다 존재한다.

추론(미검증):

- 서명된 Sparse Package의 자체 서명 인증서를 신뢰 저장소에 등록하려면 관리자 권한이 필요할 가능성이 있다.

## Decision

1. **CLI 탐색을 `github.exe` 고정에서 `github.exe` → `github.cmd` → `github.bat` 순으로 변경한다.** `.exe`는 `CreateProcess`로 직접 실행하고, 배치 파일은 `cmd.exe /d /s /c ""<cli>" "<folder>""`로 실행한다.
2. **배치 파일 경로에 `%`, `^`, `"`, 줄바꿈이 있으면 실행을 거부하고 오류를 표시한다.** `.exe` 경로에는 이 제한을 적용하지 않는다.
3. **1차 등록 방식은 서명하지 않은 loose-file 패키지(`Add-AppxPackage -Register`)로 한다.** 서명된 Sparse Package 배포는 후속 과제로 미룬다.
4. 메뉴 대상 폴더는 `IObjectWithSite`의 사이트 체인(`IShellBrowser` → `IFolderView` → `IPersistFolder2`)에서 얻고, 전달된 `IShellItemArray`는 보조 수단으로만 쓴다.
5. 프로세스 생성 시 작업 디렉터리를 지정하지 않고 상속한다.
6. 메뉴 아이콘은 탐색한 CLI 경로의 상위 폴더에 있는 `GitHubDesktop.exe`에서 가져오고, 없으면 기본 Shell 아이콘을 쓴다.
7. 매니페스트의 `Application`이 실행 파일을 요구하므로 아무 작업도 하지 않는 `GitHubDesktopExplorerStub.exe`를 패키지에 포함한다.

## Rationale

- 1: 실제 설치본이 `.bat`만 제공한다. `.exe`만 지원하면 이 환경에서 기능이 동작하지 않는다.
- 2: `cmd.exe`는 `%VAR%`를 확장하고, 배치 파일 내부의 `call ... %*`는 `^`를 재해석한다. 이를 안전하게 이스케이프하는 방법을 확립하지 못했으므로, 거부하는 쪽이 임의 명령 실행 위험보다 낫다고 판단했다. 대가는 해당 문자가 든 경로에서 기능이 동작하지 않는 것이다.
- 3: 서명 없이 개발자 모드만으로 등록·검증할 수 있고 관리자 권한이 필요하지 않다. 서명 인증서 관리는 별도 결정이 필요하다.
- 5: 저장소 폴더를 작업 디렉터리로 지정하면 장기 실행 프로세스가 폴더를 점유할 수 있다.

## Alternatives

- 1: `github.bat`가 내부적으로 호출하는 `GitHubDesktop.exe cli.js`를 직접 실행하는 방법. GitHub Desktop 내부 구조에 의존하므로 채택하지 않았다.
- 2: `%`, `^`를 이스케이프하여 허용하는 방법. 이스케이프 규칙을 검증하지 못해 보류했다.
- 3: 서명된 Sparse Package. 인증서 신뢰 설정과 관리자 권한 요건이 불명확해 1차 범위에서 제외했다.

## Impact

- PRD 21장의 "shell command 문자열 금지"에 `.bat` 한정 예외가 생겼다.
- `%`, `^`, `"`가 포함된 경로의 저장소는 `.bat` 환경에서 열 수 없다. `.exe` CLI가 제공되면 이 제한은 사라진다.
- 설치에는 Windows 개발자 모드가 필요하다.
- Explorer 메뉴 표시(AC-09)와 실제 실행은 아직 검증하지 않았다. 검증 전까지 3번 결정이 실제 환경에서 동작하는지는 확인되지 않은 상태이다.

## Follow-up Observation (2026-10-29)

- 사용자가 `installer/Install.ps1`로 설치했고, 정상 동작한다고 보고했다(사용자 보고).
- 명령 출력으로 확인: 패키지 Status `Ok`, 레거시 키와 `Open-GitHubDesktop.ps1` 부재.
- 따라서 위 3번 결정(loose-file 등록)은 이 환경에서 동작한다. 단, 패키지가 `dist\package`를 직접 가리키므로 `build.ps1`을 다시 실행하면 해당 폴더가 삭제·재생성되어 등록이 깨질 수 있다. 이 위험은 아직 대응하지 않았다.
- 위험 대응: `Install.ps1`이 `dist\package`를 `%USERPROFILE%\.GitHubDesktopExplorer\package`로 복사해 그 위치를 등록하도록 변경했다. 제거 시 `Uninstall.ps1`이 해당 폴더도 삭제한다.
- 관찰: 같은 파일을 `%LOCALAPPDATA%\GitHubDesktopExplorer\package`에서 등록하면 `0x80073CF0` / `0x80070003`(AppxManifest.xml을 열 수 없음)으로 실패했다. `%USERPROFILE%` 아래와 `E:\` 아래에서는 성공했다. 원인은 규명하지 못했다. 숨김 폴더 `microsoft.system.package.metadata` 복사 여부는 원인이 아니었다(제외한 뒤에도 실패).
- 재설치 후 패키지 Status `Ok`, InstallLocation `%USERPROFILE%\.GitHubDesktopExplorer\package`를 확인했다. `build.ps1` 재실행 후의 동작은 아직 확인하지 않았다.
- 문서 위치를 루트에서 `docs/`로 이동했다(`docs/PRD.md`, `docs/decisions/`).

## PRD Changes

- 6장: 등록 방식을 loose-file 패키지로 명시하고 Sparse Package를 후속 과제로 표기.
- 11장: 탐색 순서와 `.bat` 실행 방식, 거부 문자 추가.
- 12.1, 15, 22.7, 22.8, 26장: `github.exe` 단독 표기와 MSIX 표기 정정.
- 13장: 아이콘 출처를 구체화.
- 21장: `.bat` 한정 예외 추가.
- 24장: 실제 프로젝트 구조로 교체.
- 29장: 구현 상태 표 추가.
